Selected Work

Core Tracking Module with Complex Domain Model

Problem: The platform needed to support a more complex domain model to track multiple related entities per field and season.

Solution: Redesigned the core tracking module from the ground up to support the new data model with separate dashboards for each entity. Built the Django models, REST API endpoints, and React UI components.

Stack: Django, Django REST Framework, React, TypeScript, PostgreSQL

Outcome: Platform now manages 22,000+ fields across 5 countries for 400+ validated users.

Prioritized Async Job Queues on GKE

Problem: A single worker queue meant time-sensitive notifications were delayed behind long-running monitoring jobs.

Solution: Split the monolithic worker into 3 prioritized queues with dedicated workers and schedulers. Updated Kubernetes manifests and CI/CD pipeline to deploy the new architecture on Google Kubernetes Engine.

Stack: django-rq, Redis, Kubernetes, GKE, Cloud Build

Outcome: Notifications now process in real-time; monitoring jobs run independently without blocking user-facing features.

Offline PWA with Local Speech-to-Text

Problem: Agronomists working in remote fields with no network connectivity needed to record field audio notes.

Solution: Built an offline-first Progressive Web App with in-browser speech-to-text transcription using Vosk. Notes are stored locally in IndexedDB and synced automatically when connectivity returns. Implemented from Figma designs.

Stack: React, TypeScript, Vosk, IndexedDB, PWA, Service Workers

Outcome: Agronomists can now capture field observations in real-time, regardless of network conditions.
